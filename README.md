# Semantic Art Search Engine — CLIP Pipeline

A two-phase Retrieval-Augmented Generation (RAG) pipeline for semantic artwork retrieval over the [Rijksmuseum dataset](https://www.kaggle.com/datasets/richliao/imageNet). Instead of filtering by author or year, you can query artworks by concept, mood, scene, or visual content — entirely in natural language.

> Built for the **Modelling Week MS 2026** project (Management Solutions).

---

## Pipeline Overview

```
Images (filtered by CSV)
  └─► CLIP vision encoder ──► ChromaDB (512-dim image vectors)

Query text
  └─► CLIP text encoder ──► cosine similarity search ──► Ranked results
```

| Step | Input | Output | Key component |
|------|-------|--------|---------------|
| 1 – Embedding Ingest | Images (JPG/PNG/…) filtered by CSV | ChromaDB collection | CLIP `ViT-B/32` vision encoder |
| 2 – Semantic Search | Free-text query | Ranked artwork list | CLIP text encoder + cosine similarity |

---

## How It Works

Each image is passed through **CLIP's vision encoder** (`ViT-B/32`), producing a 512-dimensional vector. Embeddings are L2-normalised before storage so that cosine similarity reduces to a dot product, matching ChromaDB's `"hnsw:space": "cosine"` index.

At search time, the free-text query is passed through **CLIP's text encoder**, which maps it into the same shared latent space. Because CLIP was trained with a contrastive objective that aligns image and text representations, a natural-language description can be directly compared against image vectors — no intermediate text generation or cross-modal adapter is needed.

## Dataset Layout

```
rijksmuseum/
├── drawings/
│   ├── SK-A-1234.jpg
│   └── ...
├── paintings/
│   └── ...
├── photographs/
│   └── ...
├── prints/
│   └── ...
metadata_clean.csv      ← must contain at least an "id" column
```

The image filename stem (e.g. `SK-A-1234`) is used as the join key against the CSV. Only images whose ID appears in the CSV are ingested, ensuring every vector has a valid metadata entry.

## Configuration

Paths and parameters are set in the `__main__` block at the bottom of `clip_search.py`:

| Variable | Default | Description |
|----------|---------|-------------|
| `SAMPLE_FOLDER` | `./rijksmuseum` | Root folder containing category sub-folders |
| `DB_PATH` | `./vector_database_2_full` | ChromaDB persistence directory |
| `CSV_PATH` | `./metadata_clean.csv` | Path to the metadata CSV |
| `limit` (in `get_image_paths_from_csv`) | `25000` | Max images to ingest |
| `BATCH_SIZE` (in `process_and_ingest_images`) | `100` | ChromaDB insert batch size |

## Running the Pipeline

### Full run

```bash
python clip_search.py
```

### Resume an interrupted ingestion

The script fetches all already-indexed IDs from ChromaDB at startup and skips them during the loop. Simply re-run the script after an interruption — no images will be duplicated.

## Evaluation

The technical document accompanying this project defines the following evaluation framework:

- **Precision@K** — fraction of the top-K results that are genuinely relevant to the query.
- **Recall@K** — fraction of all relevant artworks in the corpus retrieved within the top K.
- **Relevance@K** — mean binary relevance score over the top-K list.
- **Qualitative inspection** — side-by-side comparison of returned images vs. query intent.

Human relevance judgements were used to build the ground-truth labels for the four reference queries used during development.
